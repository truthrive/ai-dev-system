# Documentation rule

## Scope

Applies when creating or changing documentation, or when a code change affects documented behavior.

## Rules

- Treat current source and runtime behavior as authoritative when descriptive documentation disagrees.
- Document only behavior, interfaces, and procedures that exist or are clearly labeled as planned.
- Update the smallest set of documents needed to keep affected guidance accurate.
- Use direct links and consistent terms so readers can move from routing documents to authoritative detail.
- Preserve useful existing content and remove stale claims within the changed scope.
- Do not create placeholder guidance or duplicate policy to make an area appear complete.
